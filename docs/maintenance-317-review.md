# 317：代码整理与上游 main 合并

这次做的是维护整理，没有继续调首开参数，也没有另改音效或同步算法。功能分支已合入上游 `main` 的 `e4bf4248fcf94dac46ec0fd50403853c845b635a`，并完成 Android ARM64 profile 构建。317 沿用 316 的开发包名和签名，可以保留登录及设置覆盖安装。

## 审查了哪些代码

审查起点是原上游 `b2d6a5b` 到整理前 `f980d99` 的全部差异，共 162 个文件。这个数字包含产品代码、测试、配置和文档，不是 162 个播放器模块。[逐文件清单](maintenance-317-files.tsv)列出范围及检查方式。

重点沿五条调用链检查：Dart 与原生服务之间的创建、关闭和迟到回调；点播与直播的取流、选档和地址刷新；音频焦点、音量和倍速反馈；Surface、字幕和截图生命周期；官方资产准备、缓存清理和构建输入校验。其余代码按语言完成格式、静态检查和对应编译。这个范围不能理解为所有平台、所有输入都已经逐项实测。

## 合并上游时处理的兼容问题

上游这次不只是界面更新。它把点播和直播画质从固定枚举改成对象，并调整了播放请求、依赖和桌面窗口接口。100 个上游变更文件中，14 个与我们的工作重叠；其中 5 个出现文本冲突。

- 直播刷新原来比较 `currentQn == quality`。新模型的左边是对象、右边是整数，直接保留会始终匹配失败。现按 `currentQn.code` 比较，刷新仍同时匹配协议、封装和编码。
- 点播实际画质反馈改用上游 `VideoQuality.fromFormat`，保留服务端给出的新档位和说明，不再只从旧枚举列表里寻找。
- 保留上游播放请求的新 method/data 处理，同时保留我们预取请求的账号、取消和重试标识。
- 新增的逗号、句号键倍速步进接入当前后端的支持范围；失败时保留原提示，成功提示读取当前有效倍率。
- 首页预热、官方后端设置、移动端 Surface 和自动画质菜单继续保留；桌面接口按上游迁移，桌面运行未在本轮实测。

本次没有为统一风格而批量改写与官方播放无关的上游代码。依赖使用上游锁文件，`flutter pub get --enforce-lockfile` 成功。

## 后续怎样保持写法一致

Dart 沿用仓库的 `analysis_options.yaml`，对本次修改文件执行 `dart format`，然后运行受影响测试及 analyze。不要为了让输出全绿，顺手改动无关的上游 Flutter 控件副本。

Java/C 使用仓库根目录 `.clang-format`；本轮工具为 Android NDK 28.2 内置的 clang-format 19.0.1。配置保留 include 顺序和字符串字面量，避免格式化顺带变更宏或二进制桥接代码。Python 用 Black 24.10.0；构建输入、文件范围、库身份检查必须使用显式分支，测试断言则保留在未启用 `-O` 的验证命令中。

纯格式、功能修复和上游同步分别提交。native 私有偏移修改仍须给出目标库哈希、指令守卫及失败路径测试，不能因为文件已经排版整齐，就降低这层验证要求。

## 留下的维护问题

`OfficialRuntime` 和 Dart 播放控制器仍然较大，分别承担反射桥接、预加载、资源刷新、Surface 和状态协调。它们有拆分空间，但直接抽象成多个通用框架会影响目前依赖同一队列的生命周期关系；这次没有做这种结构重写。

大量官方接口和偏移仍依赖锁定的 9.14.0。格式化、静态检查和本次回归不能把它变成公开稳定 SDK。此前暂停的首开策略取舍、其他设备校准、字幕样式及 HDR 截图保真等缺口仍按原记录保留。
